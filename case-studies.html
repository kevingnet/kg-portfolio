Three projects in more depth: what the problem was, what I did, and what changed as a result.

7 months

Recovering a stalled localization platform

Google · Sr. Software Engineer / Solution Architect · 2020 – 2022 · Java, Dart, App Engine, Datastore

Problem

Google’s global localization platform (Avik / Babel) had been stalled for two years. It ran on a ~45k-line legacy web stack that was hard to change, and it needed a proper security model for who could see and change translation work.

What I did

  • Onboarded to the Google stack and a 60k+ line enterprise codebase in about 2 months, reverse-engineering the legacy Java.
  • Led a greenfield rewrite: ~16k lines of Java backend and ~6k lines of Dart front end.
  • Wrote a ~2k-line RBAC module covering mandatory and discretionary access control, authentication and authorization, OAuth2-aware.
  • Covered it with unit, integration and performance tests on App Engine and Datastore.

Result

  • Delivered in 7 months, after two years of no progress.
  • Codebase down from ~45k to ~24k lines, with a simpler and faster operator workflow.
  • Projected ~$500k in first-year vendor savings, plus time saved for users.

80k → 8k lines

Rewriting VMware’s QA automation framework

VMware · Sr. Member of Technical Staff · 2015 – 2016 · Python, ESX, HBR, SSH

Problem

QA testing for ESX, HBR and related appliances ran on a ~80k-line, Perl-centric legacy framework. It was slow, and scripting new scenarios meant working inside low-level Perl internals.

What I did

  • Architected and built Gemini, a new Python framework that instruments virtual and physical servers, workstations and appliances.
  • Combined object-oriented structure with functional helpers and meta-programming, so tests are short and easy to extend.
  • Built the supporting libraries: an SSH connector for secure remote commands and a log framework that writes to the terminal or HTML reports.

Result

  • ~8k lines of Python replaced ~80k lines of Perl.
  • Test runs about 8× faster.
  • QA and field engineers could script complex scenarios without touching the old internals.

An OCR test system for DirecTV set-top boxes

DirecTV · Contract consulting · 2007 – 2012 · C++, ACE, ActiveX/COM, FFT, Perl

Problem

Automated testing of set-top boxes needed to read the text shown on screen from live video. A previous OCR effort, by a six-person team over four years, had not delivered a working system.

What I did

  • Designed a client/server system in C++ on the ACE framework: an ActiveX/COM control captures video frames, and an OCR server returns the text over TCP/IP.
  • Wrote the image processing: cropping, binarization and an adapted FFT, plus recognition algorithms using kernel methods and decision trees.
  • Made the clients scriptable from JavaScript so they could be driven from the Test Director web app.
  • Built a Linux socket server and Perl client driving several RedRat infrared transceivers at once, used to “blast” boxes in the server farm with random remote-control input.

Result

  • A working OCR pipeline in under 2 months, working independently.
  • Automated test runs across the server farm that found software errors without manual checking.
  • Performance and load testers for the OCR server were part of the delivery.
